# AureonX

AureonX is a multi-asset trading platform that runs on virtual funds. Users trade with a virtual balance that an admin credits, and no real money moves through the app. Never use reference-exchange names, logos, watermarks or copy anywhere.

This file is the single source of truth. It describes **what has shipped**, and nothing planned. Update it in the same change that ships something.

@AGENTS.md

  - `GET /md/v1/tickers` (route handler in the app Worker, forced dynamic, outside the proxy matcher): fetches KuCoin `allTickers`, returns only enabled markets (publishable key, RLS), at most 2 retries with jitter. In-memory caches (`stale-cache.ts`): tickers 5 s, failure 10 s, markets list 60 s. While KuCoin fails it answers 200 with `stale: true` and the old tickers (original `ts`, so the client marks them delayed) for up to 60 s after the last good fetch, then 502; the 10 s window keeps KuCoin from being called while it fails. Every failed refresh logs a JSON line and goes to Sentry with the upstream status and retry count. The Cache API works only on the custom domain `aureonx.app`, not on workers.dev; no code under `src` uses it (grep for `caches`), so `/md/v1` caches stay in memory and the move to it is open. When `/md/v1` errors the client store keeps the last good tickers on screen and they turn delayed (Delayed is judged at each poll, so with backoff it can show up to one backoff step late). ## Hard rules (non-negotiable)

1. **Money:** integer minor units (`bigint` cents), never floats. Asset quantities and prices are Postgres `numeric`, and **strings** in TypeScript. PostgREST returns `numeric` as JSON numbers, so select them with `::text`.
2. **Every balance mutation** goes through an atomic Postgres RPC with row locks. No client or server code updates balance columns directly.
3. **Options and Forex expiry is server-authoritative**, computed in the DB: `created_at + duration` for Options, `entry_price_at + duration` for Forex. Settlement is idempotent through a guarded status transition (`… where status = 'open'`), and a void refunds premium and fee through a SQL-only void job. Neither product ever falls back to a random or synthetic price. The windows differ per product:
   - Options: entry is the snapshot mid, refused (`PRICE_STALE`) unless the snapshot is at most 15 s old and not in the future. It settles only at the first snapshot with `expires_at <= fetched_at <= expires_at + 60 s`. A position still open after `expires_at + 90 s` is void.
   - Forex: a position opens `pending`, refused (`PRICE_STALE`) unless the newest `fx_prices` row is at most 70 minutes old and not in the future (a feed check, never the entry), and refused (`MARKET_CLOSED`) inside a closure or when `now + ENTRY_GUARD + 60 min + duration + 70 min` passes the next closure start. Its entry is the first `fx_prices` row with `created_at + ENTRY_GUARD <= ts <= created_at + ENTRY_WAIT_MAX` (5 and 65 minutes, on the print's own `ts`), assigned inside `ingest_fx_rates`; with none it stays pending until the void. It settles only at the first `fx_prices` row with `expires_at <= ts <= expires_at + 2 h` and `ts > entry_price_at`, compared at the instrument's `price_decimals`. A position still pending after `created_at + 2 h 20 min` or still open after `expires_at + 2 h 15 min` is void.
4. **Money paths never take a client-supplied price.** Prices are fetched server-side.
5. **Market data:** poll REST snapshots, not websocket proxies. One ticker store per tab (`use-market-data.ts`); the Spot Book, Trades and chart panels poll Vision directly for the selected symbol only, while the page is visible, under the shared host cool-down (rule 6). No leader-tab election.
6. **Upstream calls:** bounded retry with jittered backoff plus a short negative cache. Never hammer a rate-limited upstream: retry only timeouts, 5xx, 418 and 429 (at most 2 retries, 1 s floor plus jitter, Retry-After honoured when it is 5 s or less); a 418 or 429 starts a per-host cool-down (Retry-After, else 60 s) that every call to that host respects (`src/lib/market/cooldown.ts`, `retry.ts`, `http.ts`). In `price-ingest` a 418 or 429 is never retried and skips straight to KuCoin. **Exception:** the Open Exchange Rates call in `fx-ingest` has zero retries, because the claimed hourly slot in `fx_state` is its negative cache.
7. **Realtime channel names** get a `crypto.randomUUID()` suffix per mount.
8. **RLS is on for every table.** The Supabase secret / service-role key is used only in server code, Edge Functions and cron.
9. **No loosening of `tsconfig`, and no `eslint-disable` comments.**
10. **Never export `runtime = 'edge'`.** OpenNext runs the Node.js runtime.
11. **Suspension:** a suspended account cannot open exposure (Spot orders, Options and Forex positions, transfers); settlement and the void job always pay out and `admin_adjust_balance` still works (see the slice 7 migration above).
12. **Deposit and Withdraw show no wallet address and take no request.** Users never request funds; an admin credits accounts through Top-Up.
13. **KYC gates nothing**, and KYC photos live only in the private `kyc-photos` bucket under `{user_id}/`, read by admins only through short-lived signed URLs (see the slice 8 migration above).

## Compute budget rules

- Browser → Supabase directly for reads (RLS) and RPC writes. Live updates come from Supabase Realtime.
- **Never poll a Next route.** Server actions and route handlers exist only where a secret is needed, or for read-only admin queries that use the signed-in session.
- Display market data comes from public APIs in the browser, or from one shared cached route. Workers Cache hits still bill as requests, with no CPU.
- Options settlement runs inside Supabase (pg_cron + Edge Function). There is no external scheduler.
- The proxy/middleware matcher covers the protected routes plus the entry pages `/`, `/sign-in` and `/sign-up` (signed-in redirect to `/home`; no auth cookie means no token check), and verifies the JWT locally. `/sign-in/mfa` is deliberately not matched.
- Public pages are static. Do not use ISR or `revalidate`.

## Conventions

- Market ids look like `BTC-USDT`. Display them as `BTC/USDT`.
- Claude Code commits are authored as `Claude <noreply@anthropic.com>` with the trailer `Co-authored-by: apparentlybenz-glitch <apparentlybenz@gmail.com>`. The owner merges on GitHub; agents never merge.
- `AGENTS.md` is written by `next dev`. Keep it committed.
- Wording: funds are **virtual funds** / a **virtual balance**. Never describe the funds or the platform as a trial or imitation version anywhere: files, UI copy, comments, docs and commit messages. The banned words are simulated, demo and practice, plus the others listed in the Phase 2 brief. This line is the only place they may appear.
- User-facing strings go in `messages/en.json`, never hard-coded.
- Mobile first: build every screen at 390 px first; `md:` and `xl:` add the tablet and desktop layouts.
- Every scrollable page reserves bottom padding equal to the tab bar height plus the safe-area inset. Use the variables in `globals.css`, never raw `env()` or a hard-coded 56 px: `--safe-t`, `--safe-b`, `--tab-bar-h`, `--tab-bar-overhang`, `--top-bar-h`, and the `pb-tabbar` utility (tab bar + raised Trade button + 0.5 rem + `--safe-b`). The viewport sets `viewportFit: "cover"`. Spot and Options have no top bar, so their headers add `var(--safe-t)` to the top padding.

## Working rules

- PR bodies are a one to three sentence summary of what was done, with no other text.
- Docs only record what a future agent needs to read. Do not write docs for the owner.
- After any `shadcn add`, revert the `cn` package from `package.json` and the lockfile and point the component's import at `@/lib/utils`; the cn guard test (`src/lib/cn-guard.test.mjs`) enforces this.
- **UI changes need a picture.** When a pass changes what a user sees (layout, styling, components, on-screen copy), capture a still picture of the result before reporting done. Skip it for passes with no visible change (backend, migrations, docs).
  - Start the app locally with the dev server, capture, then stop the server. Use the Playwright already in the environment; add no package and change no config for this.
  - Viewport 390 by 844 first. Add 1280 by 800 only if a `md:` or `xl:` layout changed.
  - One picture per changed screen or state, saved to `/tmp`. Never put it in the repo and never commit it. Stills only, no animation capture.
  - Show the picture in the final report with the route it shows. If the surface cannot render images, give the path and say so.
  - When a screen needs a session or data, a temporary harness page (deleted before the commit) may render the real components against a local mock server and a self-signed test token; no real account and no write to any database.
  - If a screen needs a signed-in session and no test account exists, capture what is reachable and list what was not captured. Never use real credentials and never create accounts to get a picture.
